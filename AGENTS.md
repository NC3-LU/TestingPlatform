# Repository guidance

## Public communication

This repository is public. Apply these rules to committed files, commit and merge
messages, pull request titles and descriptions, issues, and comments:

- Describe the concrete change, resulting behavior, and relevant validation.
- Include technical rationale when it helps a contributor assess the code.
- Keep internal discussions, business or partnership decisions, and private
  instructions out of public text.
- Keep installation-specific hostnames, infrastructure inventories, deployment
  status, migration timelines, and recovery procedures in private operator docs.
- Use generic examples for configuration. Never include credentials, real user
  data, or unredacted environment and diagnostic output.
- Review the complete staged diff and proposed public text before publishing.
